# 第一版验证计划

## 构建与静态检查

- Release x64 主程序和原生验证目标使用 `/W4 /WX /utf-8 /permissive-` 构建。
- 构建脚本在编译后自动运行 CTest，包含 `PlayerUILogic`、`CoreLogic`、`ComparisonPlayer`、`ExportPolicy`、`Image2SequenceInput`、`PlayerEngineExportSnapshot`、`DecodeScheduler`，覆盖 UI 换算、双手柄约束、双来源最长时间轴、越界纯黑、成对提交、50/50 内存预算、播放范围循环边界、范围缓存连续计数、四档遮罩几何、导出快照、90 MB 码率、image2/ffconcat 参数、自然数字排序、缓存代次清理和解码调度。
- `verify-real-png.ps1` 使用调用者提供的真实 PNG 路径，自动验证 25%、50%、75%、100% 解码尺寸、BGRA 布局和 D3D11 上传；通用 CTest 不写入本机绝对素材路径。
- 播放器不依赖 Python、Node.js、浏览器或非系统运行时 DLL；MP4 导出调用本机 `PATH` 中已有的 FFmpeg 8.1。
- Release EXE 的 Windows VersionInfo 产品名为“序列播放器”，版本为 `0.1.0.0`。
- `ZTMediaFoundationVideoSmoke` 验证真实视频元数据、25/50/75/100% 解码、首中末帧 Seek、画面方向与连续解码吞吐；`ZTPlayerEngineVideoSmoke` 验证逐帧、范围、缓存、失败回退及 PNG↔视频 Generation 隔离。
- `ZTComparisonPlayerTests` 使用临时 PNG 来源，验证共享总帧取最大值、短侧越界纯黑、拖回恢复、最长边界循环与停止、共享 25 GB 预算、pending 期间用户最终播放意图、双路解码失败回滚以及退出对比不重载主来源。
- CMake install 包含 `THIRD_PARTY_NOTICES.md` 和 Dear ImGui `LICENSE.txt`。

## 功能验证

1. 加载目录后首帧必须显示为 `MainSeq.0516.png`。
2. 默认值必须是 `60 FPS / 25 GB / 100%`。
3. 左右方向键每次严格移动一帧，不存在跳十帧路径。
4. 时间轴拖到首、中、尾位置时，画面、帧号和文件名一致。
5. 画布横向移动 100 px 时，目标帧变化约 50 帧。
6. 依次切换 100%、75%、50%、25%，解码尺寸应分别为：
   - 1920 × 1920
   - 1440 × 1440
   - 960 × 960
   - 480 × 480
7. 降低内存目标后，缓存占用回落且当前显示帧不丢失。
8. 重新扫描失败或新首帧解码失败时，原序列保持可用。
9. 播放范围默认覆盖当前完整序列；两个手柄不可交叉，允许单帧范围，标签使用 1-based 帧号。
10. 循环开启时自定义结束帧回到起始帧；循环关闭时停在包含的结束帧并同步显示停止状态。
11. 时间轴、方向键和画布擦帧仍可定位到播放范围之外；Home/End 跳到当前范围端点，从范围外点击播放时回到范围起始帧。
12. 同目录重扫和解码比例切换保留自定义范围；完整范围模式随新增帧扩展；加载不同目录时重置完整范围。
13. 默认必须为“无遮罩”；切换四档遮罩后的居中可见区域必须分别为：
   - `1080×1080`：`(420,420) → (1500,1500)`
   - `1920×1080`：`(0,420) → (1920,1500)`
   - `1080×1920`：`(420,0) → (1500,1920)`
   - `864×1080`：`(528,420) → (1392,1500)`
14. 遮罩只覆盖图像区域，不遮住画布留白；在 `25% / 50% / 75% / 100%` 解码下必须保持相同归一化尺寸。
15. 深色主题需覆盖 ImGui、Windows 标题栏和 D3D11 清屏；启动、Resize 与最小化恢复时不应闪现白色背景。
16. `800×560 / 1339×760 / 1340×760 / 1440×900` 均不得出现顶部来源文字贴边、时间轴帧号与秒数错位、双手柄标签重叠或底部状态裁切；所有交互控件必须位于底部，播放组以窗口为基准居中。
17. 按钮、循环开关、时间轴和范围手柄的动画不得改变命中区、当前帧位置或遮罩边界；Windows 关闭客户区动画时需立即到位。
18. 首帧/末帧分别跳到自定义起始帧和结束帧；上一帧、下一帧与左右方向键仍严格一帧。
19. MP4 必须继承当前遮罩、60 FPS 和 inclusive 范围；25/50/75% 预览仍输出原始 PNG 尺寸对应的裁切。
20. 五档输出尺寸分别为 `1920×1920 / 1080×1080 / 1920×1080 / 1080×1920 / 864×1080`，均为 HEVC Main `p5`、`hvc1`、yuv420p、BT.709。
21. 拖入视频后按原生 FPS 播放；重扫与 PNG 导出禁用；左右方向键严格一帧；退出时后台视频 Seek 必须可取消且进程正常结束。
22. 只有成功拖入 PNG 目录/PNG 文件才更新 `LastSequenceFolder`；文件夹选择器、重扫、“打开当前序列”和视频拖入均不得覆盖。
23. 同一目录连续三次导出命名为 `目录名.mp4 / 目录名01.mp4 / 目录名02.mp4`。
24. 导出时显示绿色真实帧进度，完成后进度条消失；成功、失败、FFmpeg 缺失与目录不可写均不得弹窗。
25. 取消或关闭程序后不得残留 `.ffconcat`、`.part.mp4`、FFmpeg 进程或图片缓存。
26. `MainSeq.0516.png` 连续序列必须命中 `MainSeq.%04d.png`；自定义索引 100 必须映射真实 `-start_number 616`。
27. 所选范围缺帧、混合目录或非连续命名必须回退 ffconcat，并继续输出准确帧数。
28. 滤镜必须先执行 `scale=in_range=pc:out_range=tv:out_color_matrix=bt709`，不得只贴 BT.709 标签。
29. 当前帧秒数使用 `currentFrame / targetFramesPerSecond`；第一帧显示 `0.00 秒`，改变 FPS 后立即同步更新。
30. 滚轮缩放范围必须为 `25%–1600%`；未触及边界时，缩放前后鼠标下的图像坐标保持不变。
31. 中键拖动必须让画面与鼠标同向移动，不暂停播放、不改变当前帧、不提交 Seek；松开中键后停止平移。
32. “重置画面”恢复适应窗口并居中，清除缩放角标；不得改变当前帧、遮罩、播放状态、解码比例或缓存。
33. PNG 与视频必须使用同一套缩放、平移和重置行为；新来源成功提交时复位，同一来源重扫或切换解码比例时保留视图。

## 双画面对比验证

来源组合至少覆盖以下矩阵；视频↔视频与序列↔视频是主要验收路径，底层兼容能力还需保留序列↔序列等其他组合：

| 左侧主来源 | 右侧来源 | 必验结果 |
|---|---|---|
| 视频 | 视频 | 两种视频共用一个播放时钟；帧数不同时按较长视频继续 |
| PNG 序列 | 视频 | 方形序列与视频使用相同共享帧号，短侧越界纯黑 |
| 视频 | PNG 序列 | 拖放落点正确进入右侧，退出后左视频保持主来源 |
| PNG 序列 | PNG 序列 | 底层兼容路径可用，最长时间轴、恢复和内存拆分一致 |

1. 单画面状态显示“对比画面”；点击后画布分成左右两侧，按钮改为“退出对比”，右侧显示拖入来源引导。
2. 把支持的视频、PNG 文件或 PNG 序列目录拖到右侧画布，只能更新右侧来源；落点不在右侧时不得误替换右侧。
3. 右侧来源成功提交后，左右共享帧必须重置为 `0`，首个可见结果为两侧第 1 帧的成对提交。
4. 对比总帧数严格等于 `max(左总帧数, 右总帧数)`，不得取较短素材交集，也不得按归一化时长映射不同帧号。
5. 共享帧进入短素材越界区时，该侧必须清空纹理并显示纯黑；不得停留在末帧、重复末帧或拉伸素材。拖回有效帧后必须恢复对应画面。
6. 左右使用唯一共享时钟。任一有效目标帧尚未就绪时不得只提交另一侧的新帧；越界纯黑可作为该侧已就绪，与长侧有效帧成对原子提交。
7. Space、播放按钮、左右方向键、时间轴、画布擦帧、播放范围、FPS、循环、解码比例和遮罩均只产生一次共享命令，左右不得各自推进或发生双重 Toggle。
8. 左右方向键仍严格移动一帧；在任一画布横向拖动 `100 px` 时共享目标变化约 50 帧，开始擦帧后双方暂停且松开不自动恢复。
9. 循环关闭时在最长素材的共享结束帧同步停止；循环开启时从最长结束帧一起回到共享起始帧。短侧只在自身有效范围显示画面。
10. 播放范围的手柄、数字输入、Home/End 与首帧/末帧按钮使用共享最长时间轴；单帧范围和范围外手动检查仍可用。
11. 解码比例切换必须同时重建左右解码代次，双方成功后才提交共享比例；任一侧首帧失败必须把已成功侧回滚到旧比例，回滚完成前不得恢复播放或生成混合代次的成对修订号。
12. 默认 25 GB 是进程总预算。对比模式下左右缓存容量各占可用缓存预算的 50%，两侧缓存之和不得超过全局预算；退出后主来源恢复完整预算。
13. 对比遮罩必须基于每侧固定 `1920×1920` 虚拟画布：`1920×1920` 来源应用 `1080×1920` 时使用 `U=0.21875～0.78125`，已裁 `1080×1920` 视频应用同名遮罩时必须使用完整 `U=0～1`；`1920×1080 / 1080×1080 / 864×1080` 匹配来源同样不得二次裁切。小来源不拉伸，超大来源等比缩小。None 与四档遮罩的基础 canvas 显示宽高必须完全相同；若 canvas 边长为 `D`，可见开口尺寸必须分别为 `D×D / 0.5625D×0.5625D / D×0.5625D / 0.5625D×D / 0.45D×0.5625D`，禁止把 opening 单独 Fit 到 Pane。所有预设都要求左侧最终可见内容右缘、右侧最终可见内容左缘贴中线，分隔线不得被图像跨越。滚轮或中键导航后允许临时离开中线，“重置画面”必须恢复对应的完整方画布缩放和基础对齐。
14. 点击左、右画布分别建立选中状态。滚轮和中键只修改选中画布；“重置画面”只复位当前画布，另一侧的缩放、中心和画面不得改变。
15. 点击“退出对比”后，左侧来源、Generation、当前帧、缓存和视图保持；右侧引擎、纹理、缓存和视图释放。再次进入时右侧必须为空。
16. 对比中点击“导出 MP4”仍只捕获左侧主来源；右侧素材、双画面布局以及短侧纯黑段不得进入导出快照。
17. 右侧加载失败时必须保留主来源和当前画面，并以内联错误说明；不能留下半提交右纹理或改变 `LastSequenceFolder`。

## 性能验证

- 先在 50% 解码下缓存本次扫描到的完整序列，再连续播放 5 分钟。
- 实际呈现帧率目标为 60 FPS，缓存热状态不出现可见停顿。
- 后台缓存运行时 UI 输入延迟不超过 100 ms。
- 暂停状态验证 4 路后台解码可以加快完整缓存；播放状态验证后台并发自动降为 1 路。
- 快速擦帧只提交最新目标，不展示旧代次结果。
- 监控进程私有内存、缓存字节、队列长度、WIC 解码耗时和掉帧数。
- 进程私有内存接近用户内存目标约 `98%` 时，新增后台缓存应暂停；当前帧、方向键、时间轴和画布擦帧仍可用。
- 对比模式连续播放时监控左右合计缓存与进程私有内存；25 GB 总目标不得因为创建第二个引擎扩张到 50 GB，任一侧缓冲也不得让另一侧独立越过共享帧。
- 真实 `1920×1920` PNG 的 3600 帧/60 FPS NVENC 基准必须小于 60 秒；目标为 20 秒级。成品必须不超过 90,000,000 字节。
- 用户完整 2493 帧/41.55 秒/1920×1920 序列使用 HEVC Main p5 应小于 30 秒；当前实测为 9.846 秒、87,334,905 字节。

## 无持久缓存验证

- 运行前记录项目目录和素材目录文件清单。
- 播放、切换比例、重扫并退出。
- 进入对比、分别加载左右来源、擦帧到短侧纯黑区、退出对比并关闭软件。
- 运行后确认应用没有新增 `.zsf`、`.cache`、SQLite、临时图片或图片缓存目录。
- Windows 可能按系统策略将进程内存分页到磁盘；该行为不属于应用创建图片缓存文件。
- 允许存在程序自身的构建产物和注册表 `ExportFolder` 路径值；设置不得包含图片数据。
- 导出目录允许存在用户要求的最终 MP4；运行结束后不得残留导出清单或未完成视频。
- 退出对比后不得残留右侧解码线程、图片缓存文件、临时帧或持久化的右侧素材内容。
